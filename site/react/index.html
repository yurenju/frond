frond-react

frond's unstyled React component layer. Like Radix or Base UI, the parts carry no styling — every decision about appearance lives in your CSS.

The frond demo page GitHub Design decision (ADR-0011)

Installing

npm install @yurenju/frond @yurenju/frond-react react

@yurenju/frond and react are both peer dependencies — frond-react has no runtime dependency of its own, and will not quietly install a second copy of frond for you.

Using it

import * as Reader from "@yurenju/frond-react";
import { EpubBook } from "@yurenju/frond/epub";

const book = await EpubBook.open(await file.arrayBuffer());

<Reader.Root book={book} settings={{ fontSize: 20 }}>
  <Reader.PreviousTrigger>‹</Reader.PreviousTrigger>
  <Reader.Viewport className="reader-viewport" />
  <Reader.NextTrigger>›</Reader.NextTrigger>
  <Reader.Progress className="reader-progress" />
</Reader.Root>

No useEffect, no refs, not one line of cleanup code. Creating and destroying the iframe, remounting on a book change, re-laying out on a settings change, repaginating after the window changes — all of it is inside Root. The reader above is this code running — the full version is in app.tsx。

The appearance is entirely yours

Every part carries a data-frond-part, and state is expressed as attributes too — data-state, data-writing-mode, data-disabled, data-at-start. className is passed all the way down to the underlying element. 

[data-frond-part="viewport"] { block-size: 70dvh; }
[data-frond-part="viewport"][data-writing-mode="vertical-rl"] { … }
[data-frond-part="next-trigger"][data-disabled] { opacity: 0.4; }

The Default styles switch above toggles @yurenju/frond-react/styles.css. All of it is wrapped in :where() at specificity 0 — one class rule of your own beats it, with no !important and no concern for load order. Turn it off and the parts fall back to the browser's native appearance.

Inside the book does not go through CSS

The book renders inside an iframe, and outside CSS cannot reach in. Font size, line height, margin, one or two columns and the theme all go through <Root settings={…}>, and that route enforces frond's authority order: reader settings > frond's corrections > the book's declarations. So Viewport is a box, not a sheet of paper.

The Theme control in the masthead is where that shows. It is one switch for the whole site, and the book has no separate one — the page's light/dark is turned into a theme in settings, because color-scheme stops at the iframe and colours are the only way across.

Gestures are your decision

The Keyboard and swipe paging switch above toggles whether useKeyboardPaging() and useSwipePaging() are called. Without them not one gesture is consumed — "swiping left means next page" is a product decision, not a fact of frond's. Both hooks are short enough to copy wholesale and modify.
