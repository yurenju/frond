frond-react

frond 的 unstyled React 元件層。像 Radix 或 Base UI 一樣，零件不帶任何樣式——外觀的每一個決定都在你的 CSS 裡。

frond 本體的展示頁 GitHub 設計決策（ADR-0011）

怎麼裝

npm install @yurenju/frond @yurenju/frond-react react

@yurenju/frond 與 react 都是 peer 相依——frond-react 自己一個執行期相依都沒有， 也不會偷偷幫你裝第二份 frond。

怎麼用

import * as Reader from "@yurenju/frond-react";
import { EpubBook } from "@yurenju/frond/epub";

const book = await EpubBook.open(await file.arrayBuffer());

<Reader.Root book={book} settings={{ fontSize: 20 }}>
  <Reader.PreviousTrigger>‹</Reader.PreviousTrigger>
  <Reader.Viewport className="reader-viewport" />
  <Reader.NextTrigger>›</Reader.NextTrigger>
  <Reader.Progress className="reader-progress" />
</Reader.Root>

沒有 useEffect、沒有 ref、沒有一行清理程式碼。iframe 的建立與銷毀、換書的重掛、換設定的重排、視窗改變後的重新分頁，全部 在 Root 裡面。上面那個 reader 就是這段程式碼跑起來的 樣子——完整版在 app.tsx。

外觀完全是你的

每個零件都掛著 data-frond-part，狀態也是屬性—— data-state、data-writing-mode、 data-disabled、data-at-start。 className 一路傳到底層元素。 

[data-frond-part="viewport"] { block-size: 70dvh; }
[data-frond-part="viewport"][data-writing-mode="vertical-rl"] { … }
[data-frond-part="next-trigger"][data-disabled] { opacity: 0.4; }

上面那個「預設樣式」開關切的是 @yurenju/frond-react/styles.css。它整份包在 :where() 裡，優先權是 0——你自己一條 class 規則就蓋得過去，不必 !important，也不必在意載入順序。 關掉它，零件回到瀏覽器原生的樣子。

書裡面不走 CSS

書渲染在 iframe 內，外面的 CSS 進不去。字級、行高、 邊界、單欄雙欄、主題一律走 <Root settings={…}>， 那條路上壓著 frond 的權威順序：讀者設定 > frond 修正 > 書的宣告。所以 Viewport 是一個盒子， 不是一張紙。

手勢是你決定的

上面那個「鍵盤與滑動翻頁」開關切的是要不要叫 useKeyboardPaging() 與 useSwipePaging()。 不叫的話一個手勢都不吃——「往左滑等於下一頁」是產品決策，不是 frond 的事實。兩個 hook 都短到可以整段抄走改。
